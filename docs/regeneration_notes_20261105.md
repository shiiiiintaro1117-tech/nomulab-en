# 生成ツールへの反映手順（2026-11-05 点検 1巡目・2巡目分）

## この文書の目的

このリポジトリは、外部の生成ツールが書き出した静的HTMLをそのまま置く構成です。週次更新のコミット（例：`Weekly update: 2026-11-01`）を見ると、新しい記事、`index.html`、`zh/index.html`、`sitemap.xml` だけが書き出されています。一方で、2026-09-30 の `Retranslate 127 published articles` のように、既存記事をまとめて書き直す更新もあります。PR #1 と今回（PR #2）の修正はどちらも出力HTMLを直接直したものなので、次の二つの場合に元に戻ったり、新しい記事に反映されなかったりします。

- 生成ツールが既存記事を書き直したとき：タイトルや本文の修正が、元データの値で上書きされます。
- 新しい記事を書き出したとき：og:image や重複タイトルの規則は、テンプレートと生成ロジックに入れておかないと付きません。

生成ツールの本体はこのリポジトリに含まれていないため、この点検では手を入れていません。以下に、ツール側で直すべき箇所を修正ごとにまとめました。ツールにすぐ手を入れられない場合のつなぎとして、出力後に同じ規則を当て直すスクリプトを `docs/regeneration_scripts_20261105/` に置いています（最後の節を参照）。

## A. 元データ（記事のタイトル・本文の翻訳）に入れるもの

### A-1. 崩れたHTMLタグ（PR #1）

次の記事では、翻訳結果のタグが閉じていなかったため、本文の一部が表示されていませんでした。元データの翻訳文を、PR #1 のブランチ（`claude/site-review-2026-11-05`）の該当ファイルの本文と同じ内容に直してください。

- 英語：posts/2861, 3240, 3782, 4022, 5942, 401, 5755（`<br/(in fact` や `<nin addition` のような崩れ）
- 末尾の画像タグが途中で切れていたもの：posts/1597, 6525, zh/posts/7719

再発を防ぐため、品質ゲートに「`<` の直後がタグ名でも `/` でもない」「`<img` が `>` で閉じずに本文が終わる」の2つの検査を加えることを勧めます。9月の再翻訳127件の原因（画像・リンクタグの欠落）と同じ種類の問題です。

### A-2. タイトルの表記揺れとブランド名（PR #1）

PR #1 で直したタイトルは、元データ側も同じ値にしてください。対象は posts/1008, 1055, 1482, 2782, 314, 3261, 3463, 3518, 3936, 446, 4619, 5048, 5069, 5733, 5974, 7105, 7488, 765, 7720, 7858, 842 と zh/posts/7719 です。このほか、本文・Amazon検索リンク中の Kysrium→Ksyrium、Gokkiso→Gokiso、「Prime's Attaqueur」→「a Prime Attaquer」、中国語版の「小豆島に去了一趟」→「去了一趟小豆島」も反映が要ります。

ただし、これらの記事の多くは、今回の重複タイトル規則でさらにタイトルが変わっています。最終的な値は `docs/duplicate_titles_20261105.csv` の `new_title` 列を正としてください。CSVに載っていない記事は、PR #1 の値が最終値です。

翻訳プロンプトか後処理に、次の正規化規則を入れることを勧めます（今回の重複タイトル規則の第1段階と同じものです）。

- `Noma / Nomo / Nom / Nomunomu / NomuLab / Nomu Labo / Nomulab / Nomulabo / のむラボ` + `Wheel` → `Nomu Lab Wheel`
- `Nomu Lab Wheel #5` → `Nomu Lab Wheel No. 5`（タイトルでは「No.」に統一。「#」は記事番号と紛らわしいため）

## B. 重複タイトルの規則（今回）

### B-1. 規則

同じタイトル（大文字小文字は区別しない。英語は上の正規化をしたうえで比べる）を持つ記事が2件以上あるとき、その記事群の各記事に次の順で区別用の情報を付けます。読むのは本文だけで、本文の文章は変えません。

1. **記事の種類を判定する**（タイトルから）
   - 組立・交換系（built / rebuilt / assembled / replaced / laced、または「Nomu Lab Wheel」を含む。中国語は「組裝・重組・更換・號」など）→ 仕様を付ける
   - お知らせ系（comments / day off / closed / tomorrow など。中国語は「休・留言・評論・營業」など）→ 日付だけ付ける
   - それ以外（「Racing Zero」「Zonda」のようなホイール名だけのタイトル。持ち込み修理の記事が多い）→ 作業内容を付ける
2. **仕様の抽出**（組立・交換系）：本文の中で、最初に「hub」または穴数（24H、24 holes など）が出てくる段落を「仕様の段落」とし、その段落から次の値を取り出します。
   - ハブ：「○○ hub」の直前の固有名詞。翻訳揺れは正規名にまとめます（Evolight / Evo Lite / Ebolite / Evorite / Eyelite / Avolite → Evolite、Reif / Reaf / Reife → Leaf）
   - リム：「○○ rim」の直前の型番、または AL22W / XR331 / RR411db のような型番
   - 穴数：12〜48の「NNH」
   - 組み方：half-comp（semi-comp を含む）、N-cross（本文の表記のまま。日本式の本数です）、radial、JIS、Italian
   - タイトルにすでに含まれている語は付けません。
3. **作業内容の抽出**（それ以外）：rim replacement / spoke replacement / rebuild / freehub service / bearing service / crash damage / truing / tension check のうち、本文中で該当語が多い順に最大2つ（同数なら先に出てきた順）。
4. **見出しの組み立て**：英語は `元のタイトル: 抽出値, 抽出値`、中国語は `元のタイトル：抽出值、抽出值`。
5. **日付で区別する**：抽出値がない記事と、抽出後も同じ記事群の中で見出しが重なる記事には、公開日を付けます（英語 `(Oct 23, 2014)`、中国語 `（2014年10月23日）`）。
6. **記事番号で区別する**：同じ日に同じ内容の記事があるときだけ、`, entry 4902)` や `・第4902篇）` を足します（英語4件のみ）。

h1、`<title>`、og:title、JSON-LD の headline は常に同じ文字列にします。サイト内リンクの表示名（index.html の記事一覧、各記事の Related Posts）も同じ値にします。

description（meta / og:description / JSON-LD）は、対象の記事だけ「公開日 — 抽出値. 」を先頭に付け、既存の抜粋を続けて英語160字（JSON-LDは220字）で切ります。中国語は「2014年10月23日——抽出值。」です。

### B-2. 件数

| | 対象記事 | 仕様・作業内容だけで区別 | 仕様＋日付 | 日付のみ | 記事番号まで |
|---|---|---|---|---|---|
| 英語 | 1,898 | 735 | 879 | 280 | 4 |
| 中国語 | 1,239 | 590 | 353 | 296 | 0 |

英語の1,898件には、元の完全一致の重複1,802件に加え、「#5」と「No. 5」の統一や Nomulab の表記統一で同じタイトルになった記事が含まれます。適用後、英語・中国語とも重複タイトルは0件、title・og:title・headline・h1 の不一致も0件です。全件の対応表は `docs/duplicate_titles_20261105.csv` にあります。

### B-3. 生成ツールに入れる方法

- **既存記事**：CSV の `new_title` を元データのタイトルとして取り込むか、「記事番号 → 表示タイトル」の上書き表として生成時に参照してください。CSV に載っている記事は、規則を毎回計算し直さずに値を固定することを勧めます。記事が増えたときに、既存記事のタイトルが変わらないようにするためです。
- **新しい記事**：上の規則を生成時に実行し、正規化後のタイトルが既存記事（CSV の `old_title` を含む）と重なる場合に区別情報を付けます。区別した結果が既存のタイトルと重なる場合は、日付を付けます。
- **リンクの表示名**：index と Related Posts は、元データのタイトルではなく、この表示タイトルを使うようにしてください。

## C. テンプレートに入れるもの

### C-1. og:image / twitter:card（今回）

記事テンプレートの `og:site_name` の直後に、次の行を入れます。

```html
<meta property="og:image" content="{本文1枚目の画像URL}">
<meta name="twitter:card" content="summary_large_image">
```

- 画像URLは、本文の最初の `<img>` について、`<a href="…jpg">` で囲まれていれば囲んでいるリンク先（原寸画像）を、そうでなければ `src`（縮小画像）を使います。
- 本文に画像がない記事（今回は英語・中国語あわせて186件）と、記事以外のページ（index、about、guides、glossary、privacy-policy、tools、data）では、共通画像 `https://nomulabworkshop.com/og-default.png`（1200×630、今回追加）を使います。この場合は、続けて `og:image:width` に 1200、`og:image:height` に 630 も入れます。
- JSON-LD（BlogPosting）にも、`datePublished` の直後に `"image": "{同じURL}"` を入れます。

### C-2. about の記事数（今回）

「With more than 4,900 posts」を「With more than 5,300 posts translated in this edition」に直しました（翻訳済みは英語5,307記事）。about がテンプレートから生成されている場合は、件数を実際の記事数から計算して差し込むか、毎回の更新で見直してください。guides/wheel-building.html の見出し「Go deeper: 4,900 real wheel builds」も古い数字でした。全記事がホイール組みの記事ではないため、件数を含まない「Go deeper: real wheel builds from the workshop diary」に改めています。

### C-3. プライバシーポリシー（PR #1・今回）

PR #1 では description・canonical・OGP・favicon を足し、Amazon.co.jp を Amazon.com に直しました。今回は「3. Google Analytics」の節を追加し、Cookies の節にアナリティクスの用途を加え、節番号と最終更新日を直しています。手書きページであれば対応は要りません。テンプレートから生成している場合は、今回の privacy-policy.html を元にしてください。なお、privacy-policy.html だけは GA タグが入っていません（他の10,637ページには G-TCJ5CJ4XYR が入っています）。意図したものかどうかを確認してください。

### C-4. 手書きページの h1（今回）

about、glossary と guides の17ページでは、ヘッダーのサイト名とページ見出しの両方が h1 になっていました。ヘッダー側を `<p class="site-name">` に変え、CSS のセレクタも `.site-header .site-name` に合わせています（余白は従来の h1 と同じ値）。変更前後のスクリーンショット（幅375px・1280px、計38枚）はピクセル単位で一致しています。これらのページの生成元がある場合は、ヘッダー部分を同じように直してください。

### C-5. ガイド・用語集（PR #1）

guides/wheel-truing, spoke-tension, wheel-building, asymmetric-wheel と glossary の修正は、これらが手書きページであれば対応不要です。生成元がある場合は、PR #1 の差分をそちらにも入れてください。

## D. つなぎの手段：出力後に規則を当て直すスクリプト

生成ツールにすぐ手を入れられない場合は、週次の書き出しのあと、コミットの前に次を実行すれば、今回の規則（B）と og:image（C-1）が当て直されます。

```sh
mkdir -p /tmp/nomulab-work && cd /tmp/nomulab-work
NOMULAB_ROOT=/path/to/nomulab-en sh /path/to/nomulab-en/docs/regeneration_scripts_20261105/run_all.sh
```

- 作業ファイル（en.json など）は、実行したディレクトリに出力されます。リポジトリの外で実行してください。
- CSV に載っている記事のタイトルは固定値として扱います。生成ツールが元のタイトルで書き戻した記事は、CSV の値に戻ります。
- 何度実行しても同じ結果になります。適用済みの記事は書き換えず、og:image がすでにあるページは飛ばします。
- PR #1 時点のファイルにこのスクリプトを実行すると、今回のコミットと完全に一致する結果になることを確認済みです（about.html と privacy-policy.html は手で直したため対象外）。今回のコミット後の状態に対して、①旧タイトルで書き戻した記事、②旧タイトルを持つ新しい記事、の2つを再現して実行し、①が元に戻り、②に区別情報が付くことも確認しています。
- PR #1 の本文修正（A-1）とブランド名の修正（A-2）は、このスクリプトでは当て直されません。元データ側で直してください。
- 規則を変えて対応表を作り直すときは、変更前のサイトに `run_all.sh` を実行したあと、同じ作業ディレクトリで `NOMULAB_ROOT=/path/to/nomulab-en python3 docs/regeneration_scripts_20261105/make_csv.py` を実行します。
